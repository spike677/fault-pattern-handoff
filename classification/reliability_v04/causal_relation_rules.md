# 源码根动作与因果关系

先绑定版本、合同、分支和输入。记录原件中的实际操作、适用正确约定、首个可证违约和实际消费者。确认二者之间的局部计算或执行关系，再用已发布的九张卡检查必要事实和近邻。静态证据可独立支持确定结论。需要确认实际构建、动态派发或代码路径时，运行引用必须绑定 build、call_id 和路径。

| 节点 | 已证明的对象 | 计数 |
| --- | --- | --- |
| `root_action` | 当前作用域内有明确合同和实际违约的首错 | 证明首错角色后计一 |
| `independent_action` | 同案中有自己的作用域和违约依据，修复另一动作后仍可成立 | 证明独立后分别计数 |
| `downstream_effect` | 已证明的局部失效关系，受上游影响 | 0 |
| `supporting_operation` | 用于证明消费链或对照的正常操作 | 0 |
| `unknown_action` | 待证候选或合规边界 | 0 |

因果边从错误动作指向已证下游关系。`violates` 从动作指向该节点的适用合同。正常消费者的 `consumes` 从消费端指向产出被消费状态的节点，`supports` 从正常操作指向其支持的节点。`independent_of` 的两端各要有直接证据。在报告作用域引用明确作者确认，在静态作用域使用绑定合同和实际旧行为的引文。一个作用域内的作者确认可定位已证明动作，另存有效旧侧代码的位置作为旁证。未经实测的假设保留在原材料和读件说明中。引文和端点程序可验，语义蕴含由独立判卷复核。

模式结果来自正式九卡裁决，独立根数另由动作及因果证据计算。无唯一主次的多个已证明根使用 `independent`。一个根的多条关系可各带有据模式。原根裁决为缺证时，可通过同一作用域内唯一有据的直接下游叶级把该局部机理归到其已证动作上，原判和贡献节点均留痕。证据未解决独立性时，保留实现记录并给出未知角色。
