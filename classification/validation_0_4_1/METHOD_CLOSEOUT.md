## ReduceSumSquare 固定依赖补证

旧 ONNX Runtime 的 `cmake/deps.txt` 第 37 行锁定 ONNX `v1.19.1`。公开 Git 引用把标签解析至 `b751946c3d59a3c8358abcc0569b59e6ddb08cdd`。同版 ONNX 定义要求显式空轴且 `noop_with_empty_axes=1` 时保留逐元素平方。旧 CPU 路径识别这个状态，直接复制原值并早退，对 `[-2,3]` 实际产生 `[-2,3]`，约定为 `[4,9]`。结论限于固定原件的静态路径。[实际修复](https://github.com/microsoft/onnxruntime/pull/26436) · [依赖原件](dependency_supplement/original-A.json) · [绑定记录](dependency_supplement/bindings.json)

## 已开封近邻复核

三个早期独立读件中的缺证裁决均可定位原因。以相同源节选和作用域重新读件，两轮严格各 **3/3**。

| 案例 | 旧缺证的成因 | 固定范围复核 |
| --- | --- | --- |
| E03 OpenVINO 分块因果卷积 | 两轮看见窗口缺历史，却混用静态推导和报告锚点，程序拒绝决定性事实 | 作者明确定位 `Concat(past_conv,x)` 把零放到历史与真实 token 之间，卷积实际取零。报告级 C2 成立，记一个根。硬件分支与 SSM 的其他效应超出本案 |
| E07 NumPy 整数 GCD | 两轮写出吸收律，但漏填 `compliant`，程序保留缺证。属于合规状态未表达 | 满足 `gcd(1,x)=1`，循环提前结束后写回 1。静态合规，无错误动作 |
| G06 SGLang DSPARK | 两轮都定位了第二次相加，却未把已计入区间、实际消费和 C3 必要键闭合 | 初始 1000 加同一验证块 8，旧回退再加 8 后传入本地 replay。C3 成立，一个独立主动作，结论到 replay 实参为止 |
