# 候选卡：整数地址表达式表示范围不足

状态 **NEW_CANDIDATE**。本卡是审查候选，没有正式模式 ID，不进入九条分类目录或正式评分器。

**定义。** 对接口允许的逻辑位置，地址或索引表达式本应保留精确整数关系。实际执行的类型选择、转换或乘加在访存之前损失该整数关系，且失真结果被目标内存访问消费，造成实际位置与适用映射约定不符。

所属拟议父层为寻址映射。它与 L2 的区别是量纲保持正确，丢失发生于整数表示范围；与 NUM-01 的区别是语义对象为精确整数位置而非浮点累加状态。

## 必要条件

1. **同版适用合同。** 指定合法输入、逻辑坐标、对象范围、布局和单位。不能把合同外索引硬归实现缺陷。
2. **精确应有值。** 给出本案精确整数偏移及几何关系。足够内存不等于地址表达式自动可表示。
3. **实际表示。** 从实际操作数、隐式提升、窄化转换及每次表达式的结果类型确定宽度和符号。仅知道最终变量或输出类型不足。
4. **首个表示失真。** 找到精确整数超出实际范围或转换丢失的位置，区分乘法、加法、转换及最终整数地址加法。
5. **实际消费者。** 同一路径中的 gather、scatter、load、store 或指针形成消费了错误量。正常死值、先检查后回退或重新计算不得补成实际地址错误。
6. **近邻排除。** 单位换算、错误连续布局、漏基址、输入越界、分配过小、浮点中转、同步和悬空指针分别核对。
7. **可恢复对照。** 在导致首错的运算之前保持足够表示范围，或采用合同允许且正确的回退，能够保留同一逻辑映射。事后转为宽类型不能作为恢复证明。

## 已核正例与限制

GridSampler 支持 signed int16 前向、反向两处；NLLLoss2d 支持报告平台上的 signed int32 backward 起址；FlexAttention 支持报告域的 int32 tile 偏移，并恢复了相关固定 vLLM 和 PyTorch 模板。无符号类型和更宽整型具有相同精确表示关系，但本轮没有独立无符号真实正例，不能对其泛化作已验证声明。

“回绕”是当前报告中观察到的一种表现，卡片定义不要求所有语言都保证模运算。源级 C++ 有符号溢出为未定义行为，实际平台表现须有自己的证据；仅根据机器补码模型不能声称某个编译结果已发生指定地址回绕。

## 排除与不充分证据

- 位宽、dtype、大尺寸、越界告警或补丁增加 int64 单独出现。
- offset 超对象合法范围但整数仍完整可表示。
- 源公式漏基址或不正确的 stride；这种错误在无限整数精度下仍存在。
- element/byte/bit 转换错误，按现行 L2 判断。
- 浮点状态在归约更新间重复丢失，按 NUM-01 必要条件审查。
- 异常量从未被目标地址消费者采用，或合法回退保留同一映射。
- 只有另一版本的宽类型补丁，没有旧类型与消费链。

## 动作与计数

分类单位为有证据的表示失真动作及其局部地址关系。多个 load/store 正常消费同一个坏偏移时不增加根数。不同分支各自形成错误地址、分别有合同与消费者，并可在修复另一动作后仍独立违约时才增加独立根。选择窄模板与缺少范围守卫可能是同一动作的替代修复位置，不能仅凭两个可修改点计两根。
