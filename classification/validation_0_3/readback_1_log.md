# 0.3 一次事实提取记录

本次为共享环境中的开发自检，三个案例均为已见材料。执行处于同一工作区，无法据此主张环境隔离、案例未见性或独立验证。

## 实际工具和输入

- 在 `D:\project\精度\fault-pattern-handoff` 使用 `functions.exec` 调用 PowerShell 的 `exec_command`。第一批以 `Get-Content -Raw -Encoding UTF8 -LiteralPath` 读取 `classification/catalog.json`、`classification/validation_0_3/PROMPT.md`、`classification/validation_0_3/readback_A.json`。
- 第二批从固定目录单独查看 C2 必要事实及结果策略，并用 `ConvertFrom-Json` 和按换行拆分的方法输出 A 包视图内的一基行号。只依照 A 包已有的文本阅读证据。
- 写入时按 A 包中的 `source_id` 和行范围直接生成逐字引文，保留空白和 diff 符号，并核对案例顺序、作用域、角色和引文。
- 本次事实提取只交付事实包和日志。配套分类由当前验证流程调用冻结的本地分类器生成。

## 判据和边界

- `r03-1`。`old-edge` 定位旧版提前写零。`diff` 展示被绕过的范围计算和累加，也给出修订后的闭区间条件。`shared-coordinate` 给出中心坐标关系。对一维满足材料条件的示例，目标长度 3、上游梯度长度 2，左 pad 为 −3、右 pad 为 2，末坐标的中心为 −1，保留区间为 [0,1]。旧分支在该中心写零，所以本应各计入一次的两个上游梯度项都未到达目标。该复算只支持受评静态分支，未核查调用进入条件、具体构建或运行。
- `r03-2`。教程将 `pl.load` 的部分块结果直接连到 `row_max`，并报告零填充参与且主导了全负候选的结果。依据直接陈述记录将带零填充的负载送入归约的实现动作。教程的最小值填充和整块行为是报告中的对照。未知填充、屏蔽与调用链各阶段的具体责任及故障构建。
- `r03-3`。报告给出各 rank 的原始部分量、第一次 TP all-reduce 产生的完整和、后处理在同组加和同源副本三步。对同一目标，从每个部分量应计一次与报告的加和关系得出超额计入。报告直接支持后处理的具体消费动作。最早错误动作、各阶段职责及逐 rank 运行缓冲未核。
