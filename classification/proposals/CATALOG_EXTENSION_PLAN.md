# v0.4 目录扩展方案

当前执行基线为 `MECH-v0.3` 和事实、评分协议 `0.3.1`。候选登记用于把历史谓词、已证动作和后续近邻连起来。两条现有模式的跨算子验证仍待完成。当前方案进入候选审查，正式准入和版本迁移尚未放行。[候选登记](candidate_registry.json) · [历史关系](../history_mapping/HISTORY_MAPPING_REPORT.md) · [七模式覆盖](../coverage_v1/COVERAGE_REPORT.md)

## 版本与兼容

| 项目 | 实施方式 |
| --- | --- |
| 历史兼容 | 用完整的 `namespace:id` 引用已封存判决。v0.3 的既有引用、原件、锁定、评分和修订文件均按原版本复算 |
| 目录加载 | 新目录使用版本化入口显式选择 `catalog_version`、`fact_protocol`、`predicate_registry_version`，由冻结清单记录各自的内容哈希 |
| 父类和叶级 | 在目录声明稳定 ID、父类、父类事实、作用域规则及兼容组合。加载时检查重复、环、悬空引用、组合范围和主候选歧义 |
| 谓词执行 | 目录只引用注册过的检查器名和受约束参数。程序验证命名、必需字段、证据等级和适用声明。新叶复用已有检查器时只改声明、来源和测试 |
| 事实输入 | 由冻结目录生成读件事实键和模式引用的枚举。事实锚点、版本比对和局部证据范围由协议控制 |
| 固定依赖约定 | 增加可验证的依赖声明、上游提交与适用路径关联，并分别保存旧实现和合同的原始版本。先验证依赖清单及标签解析，再让此类合同作为对应旧路径的 requirement。代码、diff、运行锚点继续按自身边界检查 |
| 评分 | 评估器从冻结目录解析标签、父类、兼容关系和主目标。旧成绩按原协议复算。合并、拆分或更名用显式兼容关系和说明另存 |
| 触发和取证 | API42 给角色与语义约定，V4／55 关联测试触发和用例。CANNBot 提供检查路径，FaultAudit 提供证据绑定，FM/N 保存历史身份 |

## 当前代码的最小迁移点

1. `classify.validate_catalog` 仍用 `LEGACY_OPERATION_FACTS` 限定七个 ID。保留旧版本入口，通过新版本目录的结构校验、稳定引用和声明式检查器启用新机制。
2. `verdict` 里参与类上位和反证规则直接访问 C1。将约束改为声明，例如上位判决需要指定的实际消费事实且无同期排除。C1+C2 兼容组合仍由目录列出，动作与独立计数由因果层处理。
3. `check_calculation` 的几个比较器已是通用运算。注册预期与实际的相等、小于、大于等比较规则，把各模式的选择放进事实声明，并保持程序统一验证输入及声明范围。
4. `evaluate.freeze` 从当前目录加载固定文件。扩展后让冻结清单保存选择的目录及谓词文件映射，复算依据冻结清单解析。模型响应 schema 从该组合生成，历史 schema 与锁定文档继续可读。
5. 用原七模式覆盖同一批固定原件和锁定事实，验证迁移前后相同判决、角色、证据边界和评分。对重复 ID、循环、坏引用、未注册检查器、越域事实和同根重复计数分别做回归。固定依赖约定用 V404 验证真实版本关系，反测未绑定、错误标签和无关合同。候选通过近邻、反向对照和新事件验证后，才进入正式版本。

## 候选分工

- 首批 P0 比较低精度累加状态与不稳定求值式。分别固定参与项重数、算式及精度约定，再检查发生首错的节点。
- V406 的 FSDP 双轮在局部范数平方处定位首次溢出，归约前各分片均参与一次。它提供了中间表示范围的独立目录外证据。比较它与 NUM-01 在每步保存窄累加状态的发生位置，避免仅凭同是 FP16 合并机制。[新案逐案核对](../validation_0_3_1/coverage_holdout/COVERAGE_HOLDOUT_REPORT.md)
- 控制信息按参数角色、内部数据源绑定和执行计划检验。只有同一受评路径中实际消费者成立时才定位独立动作。
- P1 保留一般基址、生产消费表示、同步代际与存储生命周期的对照，按不同根机制持续积累证据。
- 对源件尚不能闭合的候选，仅登记可检验的必要条件和缺证。自动事实、专家判卷和测试条件按各自版本记录。

每项候选都可提出注入动作和观察位置。此处给出候选级验证设计，具体目录和注入实现按阶段四的实际验收结果发布。
